# RPC protocol (RU)

**Дата:** 17 октября 2026

## Транспорт и формат

GeoCoin реализует **JSON-RPC 2.0 поверх HTTP**:

- HTTP метод: `POST`
- Тело: объект запроса или пачка до 10 запросов.
- Успех: `{"jsonrpc":"2.0","id":1,"result":...}`.
- Ошибка: `{"jsonrpc":"2.0","id":1,"error":{"code":...,"message":...}}`.

Ответ содержит ровно одно из полей `result` и `error`, согласно
[контракту ответов JSON-RPC 2.0](https://www.jsonrpc.org/specification#response_object).
`getrpcinfo.api_version` равен `"1"`. До запуска проекта используется версия API 1;
версия 2 предусмотрена для будущего пересмотра API после запуска.
Клиент проверяет наличие `error`;
успешный ответ больше не содержит `error: null`.

Корректный запрос без `id` — уведомление: метод выполняется без JSON-ответа,
в том числе при ошибке выполнения. HTTP возвращает `204 No Content` для отдельного
уведомления или пачки только из уведомлений. В смешанной пачке уведомления
пропускаются в ответе. Явный `"id":null` получает ответ. Ошибки прогрева сервера
сохраняют идентификаторы и соблюдают эти же правила пачек и уведомлений.

`params` принимает массив или объект с именами из `getrpcinfo.param_names`.
Пропущенные необязательные именованные параметры используют значения по умолчанию,
даже если задан более поздний параметр. Пустой `{}` допустим у метода без аргументов.
Пропуск обязательного аргумента и неизвестное имя параметра приводят к ошибке.
Входные расширения: отсутствие `jsonrpc` допускается, а `params:null` означает
отсутствие аргументов; ответы всегда содержат `jsonrpc:"2.0"`. Некорректный объект
запроса получает ошибку с `id:null`, если корректный идентификатор не задан.

Целочисленные параметры отклоняют boolean, дробные JSON-числа, отрицательные
значения для беззнаковых полей и выход за диапазон целевого типа. Усечения и
переполнения при преобразовании нет. Для сумм в GC используется отдельный точный
разбор денежных значений.

Реализация: `src/geocoin/rpc/rpc_protocol.cpp` (HTTP),
`src/geocoin/rpc/rpc_server.cpp` (жизненный цикл и dispatch) и
`src/geocoin/rpc/rpc_server_security.cpp` (аутентификация и rate limit).

## Географические координаты: контракт версии 1

Координаты блоков заданы в **WGS 84, географическая система 2D**. Широта
геодезическая, положительная к северу; долгота положительная к востоку.
Высота и точность физического измерения не подразумеваются. Основа системы:
[определение WGS 84 от NGA](https://earth-info.nga.mil/?action=wgs84&dir=wgs84).

- Именованные целочисленные поля `latitude_ndeg` / `longitude_ndeg` содержат
  **наноградусы**: для градусов делить на `1 000 000 000`. Допустимые диапазоны:
  `[-90 000 000 000,90 000 000 000]` и `[-180 000 000 000,180 000 000 000]` соответственно.
- Порядок осей **EPSG:4326**: широта, долгота. GeoJSON использует
  **OGC:CRS84**: **[долгота, широта]** в десятичных градусах, согласно
  [RFC 7946, разделам 3.1.1 и 4](https://www.rfc-editor.org/rfc/rfc7946.html#section-3.1.1).
  В геометрию не добавляются устаревшее поле `crs` и вымышленная высота.
- `geo_tag` сохраняет упаковку GeoCoin v1 для **угловой ячейки 0,1°**:
  `(latitude_index << 32) | longitude_index`. Индексы отсчитываются от -90°
  широты и -180° долготы. Это собственная сетка GeoCoin; равенство площадей
  ячеек не заявляется. Индексы широты: `0..1799`, долготы: `0..3599`.
  Северная и восточная границы относятся к следующей ячейке.

Подробные ответы `getblock`, `getblockbyheight`, `getblocktemplate` и
`powdeterminism` содержат объект `geography`. Пример для генезиса:

```json
{
  "datum": "WGS 84",
  "crs": "OGC:CRS84",
  "coordinate_order": ["longitude", "latitude"],
  "angular_unit": "degree",
  "integer_unit": "nanodegree",
  "algorithm": "GeoPoW",
  "algorithm_version": 1,
  "grid_step_degrees": 0.1,
  "status": "exact",
  "latitude_ndeg": 48851583000,
  "longitude_ndeg": 8897278000,
  "point": {"type": "Point", "coordinates": [8.897278, 48.851583]},
  "cell": {
    "bbox": [8.8, 48.8, 8.9, 48.9],
    "center": {"type": "Point", "coordinates": [8.85, 48.85]}
  }
}
```

Порядок границ `bbox` по RFC 7946, разделу 5: **[запад,юг,восток,север]**.
Для каждого блока после генезиса точка GeoPoW по определению равна центру выбранной
ячейки. Генезис сохраняет фиксированную точку `[8.897278,48.851583]` внутри исходной
ячейки. `status=exact` означает корректную точку; `invalid_tag` — индексы вне сетки;
`tag_mismatch` — явно переданная точка не согласована с ячейкой. Некорректные точные
поля равны `null`.

GeoPoW v1 выбирает ячейки по всей Земле из **хеша родителя и Median Time Past
родителя**, используя только целые числа. Вероятности широтных полос распределены
по площади поверхности эллипсоида WGS 84 и квантованы в 2³² билетов. Для долготы
применяется выбор с отбрасыванием остатка, устраняющий смещение по модулю.
Доступны все 1800 широтных полос и 3600 долготных столбцов. Таблицу CDF в коде
воспроизводит `tools/generate_geopow_grid.cpp` через закреплённую GeographicLib
2.3.0. Ячейки остаются угловыми, 0,1°; равенство вероятности на м² ограничено
квантованием билетов. Это условные отметки. Шаг хранения 10⁻⁹ градуса не является
точностью межевания.

Сохранённый `geo_tag` позволяет получить каноническую точку без старых заголовков
MTP. `listblockgeography (from_height=0, limit=100)` возвращает высоту, хеш,
метку, `index_pruned` и `geography` активной цепи, включая pruned-историю;
максимальный размер страницы — 1000. При удалении заголовка его активный хеш и
метка атомарно сохраняются в записи 40 байт. Для оставленных заголовков отдельной
копии нет. Форки не попадают в исторический каталог; реорганизации оставленной
части цепи сразу отражаются в выдаче.

Географический workflow сравнивает точный контрольный отпечаток между Linux
GCC/Clang x86-64, Linux ARM64 и Windows Clang. Проверяются GeoPoW, канонические
байты метаданных, округлённые расстояния/площади и решения геометрии.
Правила и API остаются **версии 1**, разбор старых форматов не добавляется.

## Аутентификация (обязательно)

Используется HTTP Basic Auth (user/pass).

Важно: если `rpc_user` или `rpc_password` пустые, запуск сервера
отклоняется (fail-closed). См. `RPCServer::start` и `RPCServer::authenticate`.

Для ошибок аутентификации действует экспоненциальная задержка. Лимит запросов
по умолчанию выключен (`rpc-rate-limit=0`); при ненулевом бюджете превышение
даёт `429 Too Many Requests`.

## Пример запроса

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "getblockhash",
  "params": [100]
}
```

## Примеры (curl)

Рекомендуемые переменные окружения:

```bash
export RPC_URL="http://127.0.0.1:8778/"
export RPC_USER="user"
export RPC_PASS="pass"
```

Порты по умолчанию зависят от сети и печатаются нодой при старте (или задаются через `--rpc-port`):
- mainnet (`degree`): `3033`
- testnet (`degree-test`): `13033`

Вызов `help`:

```bash
curl -sS -u "$RPC_USER:$RPC_PASS" -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"help","params":[]}' \
  "$RPC_URL"
```

Справка по конкретному методу:

```bash
curl -sS -u "$RPC_USER:$RPC_PASS" -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"help","params":["getblock"]}' \
  "$RPC_URL"
```

## Ошибки

Код и сообщение возвращаются в `error`:

```json
{
  "jsonrpc": "2.0",
  "error": { "code": -32602, "message": "..." },
  "id": 1
}
```

Список кодов: `include/geocoin/rpc/rpc_types.hpp` (`RPCErrorCode`).

## Help / интроспекция

- `help` — список методов или справка по конкретному методу.
  - `help` → выдаёт методы, сгруппированные по `category`
  - `help "getblock"` → печатает точную сигнатуру/поля из `RPCCommand::help`
- `getrpcinfo` — машинно-читаемый реестр методов: `api_version`, `name`, `category`, `role`, `capabilities`, `requires_wallet`, `param_names`, `mutates`, `side_effect_free`, `stability`, `since`, `deprecated`, `deprecation`, `side_effects`.

Документируйте интеграции через `help`, если нужен «точный» контракт параметров.

## Роли RPC

RPC credentials разделены по ролям:

- `admin` — wallet/admin операции и read-only методы.
- `readonly` — только методы с ролью `readonly`.
- `miner` — только внешний майнинг (`getblocktemplate`, `submitblock` и miner telemetry).

Роли не являются полной иерархией: `admin` не вызывает miner-only методы, а `miner` не вызывает обычные readonly методы. Проверяйте поле `role` через `getrpcinfo`.
