# Инструкция: создание NFT в GeoCoin-Qt

Эта инструкция описывает, как создать NFT через графический интерфейс **GeoCoin-Qt** (страница **NFT** → кнопка **Create NFT**).

## Предварительные условия

- Кошелёк должен быть **создан или загружен**.
- На балансе должны быть монеты для оплаты **комиссии (Fee)**.
- Нода должна быть запущена (в Qt она запускается автоматически при старте приложения).

## Где находится создание NFT

- Открой страницу **NFT** (кнопка/пункт меню NFT).
- Нажми **Create NFT**.

Откроется форма создания NFT.

## Поля формы Create NFT

### 1) Name
- **Обязательное** поле.
- Любое короткое имя NFT.
- Участвует в формировании `nft_id` (ID NFT).

### 2) Description
- Описание NFT (многострочное).
- Участвует в `nft_id`.

### 3) Image URI
Есть 2 варианта:

#### Вариант A — локальная картинка (рекомендуется)
- Нажми **Browse...**.
- Выбери файл изображения (`png/jpg/jpeg/webp/bmp/gif`).
- Приложение скопирует файл в директорию данных кошелька в подпапку:
  - `nft_images/`
- Поле **Image URI** будет заполнено строкой вида:
  - `local://nft_images/<имя_файла>`

Это удобнее, чем абсолютный путь, потому что NFT-метаданные остаются стабильными и не зависят от расположения файла на диске.

#### Вариант B — ссылка (IPFS/HTTP)
- Можно вручную вставить:
  - `ipfs://...`
  - `https://...`

Важно: любое изменение **Image URI** меняет `nft_id`.

### 4) Location name
- Произвольное название места (например: `Red Square`).
- Участвует в метаданных.

### 5) Tags (comma-separated)
- Теги через запятую, например:
  - `moscow, landmark, travel`
- Пробелы по краям тегов автоматически игнорируются.
- Участвуют в метаданных.

### 6) Координаты (lat/lon) — полигон

NFT привязан к географической области, заданной **многоугольником** (список точек lat/lon).

- Ввод производится в **градусах**.
- Внутри кошелёк конвертирует их в `microdegrees` (× 1e6).
- Допустимые диапазоны:
  - широта: `-90..+90`
  - долгота: `-180..+180`

### Упрощённый режим: центр + размер (метры)

В диалоге Create NFT есть строка **Center lat/lon + size (m)**:

- **Center latitude (deg)** — широта центра (из карт)
- **Center longitude (deg)** — долгота центра (из карт)
- **Size (m)** — примерный размер области в метрах
- **Auto-fill square** — автоматически заполнит 4 точки квадрата

`Size (m)` используется как «полу-сторона» для построения квадрата. Это не точная площадь, а удобный способ быстро получить валидный полигон.

### Как получить координаты

Проще всего взять несколько точек из карт по границе участка.

Пример:
- `55.752220`, `37.615560`

#### Важно (валидность)
Полигон должен быть **невырожденным**:
- Минимум 3 точки.
- Точки не должны дублироваться.
- Площадь не должна быть нулевой.

Если полигон вырожденный, транзакция создания NFT будет отклонена валидатором.

#### Как хранится внутри
Внутри транзакции координаты переводятся в **microdegrees**:
- `udeg = round(deg * 1e6)`

И из полигона вычисляется консенсусное поле `area_bits`.

### 7) Fee (GC)
- Комиссия за создание NFT.
- Минимум: **0.000005 GC** (500 angles).
- Должно хватать баланса на оплату комиссии.

### 8) Royalty percent
- Роялти создателю (0..100%).
- Внутри переводится в basis points (0..10000).

## Подпись и пароль

## Кадастровые поля (опционально)
Если заполнить **Cadastral number**, NFT рассматривается как кадастровый участок:
- проверяется уникальность кадастрового номера
- запрещены пересечения участков
- площадь участка сверяется с `Official area (sqm)` (допуск 10%)

Поля:
- **Cadastral number** — кадастровый номер
- **Land category** — категория земли
- **Permitted use** — разрешённое использование
- **Official area (sqm)** — официальная площадь
- **Ownership doc hash / Technical plan hash** — SHA-256 хеши документов (hex)
- **Photo hashes** — список SHA-256 хешей фото (через запятую)
- **Market value / Cadastral value** — стоимость в GC
- **Last valuation date** — дата последней оценки
- **Restrictions** — ограничения/обременения (через запятую)
- **Has buildings / Building count** — наличие/количество строений

- Если кошелёк **зашифрован**, при отправке транзакции приложение попросит пароль.
- Пароль используется для подписи транзакции.

## После нажатия OK

- Создаётся транзакция типа **NFT_CREATE**.
- NFT получает `nft_id` = хеш от метаданных.
- Транзакция отправляется в ноду через `WalletModel`.

Если транзакция успешно отправлена, появится сообщение:
- `NFT create transaction sent.`

## Частые ошибки

- **Name is required** — не заполнено поле Name.
- **Invalid fee** — комиссия = 0 или отрицательная.
- **Failed to create NFT transaction** — общий отказ создания/подписи/отправки, частые причины:
  - недостаточно средств на комиссию
- некорректный/вырожденный полигон
  - неверный пароль (если кошелёк зашифрован)
  - нода не принимает транзакцию

## Примечания

- Любое изменение полей метаданных (включая координаты и теги) меняет `nft_id`.
- `local://...` — это строка метаданных. Чтобы показывать изображение в UI по `local://`, понадобится отдельная логика отображения (пока это просто ссылка/идентификатор).
